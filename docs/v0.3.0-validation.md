# v0.3.0 implementation and validation

Executed 28 October 2026 on `develop`, baseline
`580e54939cd17d02a8662e4102a1ea5d8262bf0d`.

## Result and boundaries

**GO for review/use on the tested PrestaShop 9.0.0 + PHP8.4 + Classic target.**
No unresolved defect was demonstrated by this run. **NO-GO for Marketplace
publication** pending the licensing/branding/metadata/official validation work in the
historical reports. Other themes, one-page checkouts, PS9 minor/PHP versions,
screen-reader behavior and restricted employee profiles are not certified here.
No order/payment submission was tested. No production deployment or main change.

## Implementation

Shared signal definitions/translations now have independent home/product/checkout
placement rows, visibility, priorities and links. One renderer handles all contexts,
without a display cap or required storefront JavaScript. New UI signals have no
persistent ID until Save. Placement priorities include zero; ties use persistent ID.
Strict SVG, session CSRF, authorization, transaction/lock/revision/file handling and
500-code-point plain-text limits remain enforced. Metadata and aggregate uploads
have separate 2MiB budgets; PHP limits still apply, with truncation detection.

The additive 0.3 migration widens old ordering and backfills only product placement
rows. It preserves IDs, translations, SVG references/bytes and legacy click behavior.
Home/checkout require merchant opt-in. Legacy columns remain, and repeated migration
preserves edited/new placement settings. DDL is not transactional; failed upgrades
must be retried normally after correcting the cause. Never downgrade old writers or
use an old configuration tab against the migrated tables.

Hooks: `displayHome`, `displayProductAdditionalInfo`,
`displayCheckoutSummaryTop`, `actionFrontControllerSetMedia`. Native Classic checkout
provides the summary hook; unsupported themes/checkouts produce no component. No
checkout DOM injection or core-template override is used. Checkout CMS links open a
new tab with noopener/noreferrer and visible notice; checkout anchors are rejected.
Home/product anchors remain explicitly merchant-chosen local theme IDs.

## Environment and data safety

Used the previously installed real PrestaShop9/Apache/PHP8.4 runtime and a **new
copy of its disposable MariaDB11.4 volume**, on a separate test network. The original
DB container stayed stopped throughout. The runtime's DB routing was checked against
the clone hostname before seeding/resetting synthetic audit data. Tests used
localhost-only HTTP, Chromium154/Playwright Core, two existing audit shops and EN/FR.
No actual merchant database was modified. The installed module was upgraded through
the normal PrestaShop upgrade path, never uninstalled or reinstalled. Runtime source
files/routing were backed up and restored after testing. Original test services were
returned to stopped state. A full duplicate app container was abandoned because of
disk limits; this did not weaken the database isolation.

## Defects caught during implementation

- Real PS Db::getRow appends LIMIT1: SHOW COLUMNS metadata inspection was incompatible.
  Migration now uses a SELECT against information_schema; adapters emulate LIMIT1,
  and actual upgrade/retry passed.
- Existing production Smarty compilation and CCC CSS survived file replacement.
  Successful upgrade now clears compiled Smarty and native theme asset caches;
  BO assets and registered frontend CSS are versioned. Actual browser changed from
  stale horizontal product layout to vertical without reinstalling.
- JavaScript's truthy fallback replaced numeric priority0 with an editor default.
  Nullish fallback now preserves zero; dedicated DOM assertion passes.

placements,100 repeated service calls in one CLI process:

| --- | ---: |
| Configuration load (three tables) |0.381 |
| Homepage presentation (five signals) |1.890 |
| Product presentation (three signals) |1.052 |
| Checkout presentation (two signals) |0.716 |

Includes SQL/native CMS handling and strict custom SVG validation. This is a local
microprofile, not a full HTTP load/concurrency benchmark. Queries disable result
caching; per-render dedup avoids repeated CMS generation and identical icon checks.
No persistent configuration/icon cache was introduced. Very large counts remain
proportional work; normal-use counts are bounded by payload/PHP limits, not display
truncation. Earlier SVG measurements remain historical, not new benchmark results.

## Existing-store update and manual acceptance

Follow the exact Git pull and normal module upgrade commands in [README](../README.md#update-an-already-installed-local-store).
Back up DB and uploads together; close old configuration tabs. Check version0.3.0,
placement table and all four hooks after Upgrade. Existing signals should still be
product-only until explicitly selected elsewhere. Do not uninstall/reinstall.

1. Homepage: select five signals, assign distinct priorities, Save/reload. Verify all
   five, wrapping on mobile, no link where configured, localized CMS destinations and
   only anchors known to exist in this theme.
2. Product: select a different subset/order; verify vertical rows and product-only
   CMS/anchor choices. Disable one globally and clear one translation; check omission
   in the correct contexts without fallback or broken icons.
3. Checkout: add a product to cart and enter native checkout; verify the compact
   selected subset, new-tab CMS notice and working keyboard focus. Complete sandbox
   checkout validation/payment with the store's own payment test setup; this run did
   not submit an order. Test each third-party checkout/theme separately.
4. Save again from each intended shop context; confirm shared configuration with
   shop/language-correct CMS links. Check stale-tab rejection, failed-upload error,
   explicit removal and unchanged other-placement priorities. Never test destructive
   lifecycle steps on merchant data.
